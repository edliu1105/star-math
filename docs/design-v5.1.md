# 星星回家 v5.2 修订设计（Round 3 · 已按复审 4 条最小清单修订）

## Round 3 修订（对应你复审的最小清单 1–4）

### 修 1a：W2-L4 双座救援舱 —— 孩子做什么、哪步提交
海滩上 2×d 只海龟两两站好（看得见成双）。孩子的核心操作：**点一只狗 = 派一个双座舱滑下**，
舱停稳后自动吸附最近的一对海龟（吸附动画孩子看得见"一舱装两只"）。
孩子要自己判断派几个舱，觉得够了按绿色「出发」= **提交**。
判定：舱数 === d。少派→没上舱的两只海龟原地闪黄"还有两只没位置"；多派→空舱打个哈欠自己滑回坡道（不计错）。
成功后安全带拉直、折叠成 2×d 阵列、亮 2/4/6/8。

### 修 1b：W5 能量十仓 —— 每关孩子做什么、哪步提交
- L1 充能：英雄在门口排队，**孩子逐个点英雄**→跑进机器投球（a 个红投完轮 b 个蓝）。球投完后屏显"?"，
  孩子**逐格点亮清点**（点过的格出编号徽章、不能重复点，同 W2-L3 点名机制）——**点完最后一格即提交**，数字自动显形。
- L2 断电：传送门吸走 k 颗（格子逐个熄灭）后，孩子同样**逐格点亮剩余的格**清点，点完最后一亮格即提交。
- L3 全息缺口（原文已写清：点传送门补球补到刚好，缺口格全部点亮即提交，多点一次"嗡"声不出球）。
- L4 凑十爆仓：门口排着 5 颗球，**孩子逐颗点球送进仓**；第 9、10 颗触发锁仓盖章动画后，
  孩子继续把剩下 3 颗点进第二仓——**最后一颗球入仓即提交**，屏自动显形"10 和 3 = 13"。全程孩子亲手投每一颗。

### 修 2：W3-L4 成功门槛
判定收紧为 `allocated===n && left===right` 且发生在**最后一块落下时**。
若 allocated===n 但两边不等：重的一盘弹出一块跳回地面（"这边太重啦"），继续分——过程不计错。
分配中途任何时刻都不判定（杜绝 0=0、1=1 提前通关）。

### 修 3：W6-L4 残影序列
残影从 {2,2,1} 的全部排列中**随机选一个 ≠ 孩子实际序列**的排列重跳
（孩子 2+1+2 → 残影跳 2+2+1 或 1+2+2）。两条不同顺序的弧链落在同一石墩 → 换序不变才真正显形。

### 修 4：星轨记账闭合
计数单位=**每轮一段**：每世界一次 session 5 轮，每通一轮点亮一段星轨（= 现有一颗参与星）；
星轨全程共 **10 段**（= STARS_FULL=10，两次 session 集满）；十段全亮 → 星座绽放（复用现有 constellation）。
测试钩子：`window.__trail={world,seg}`，seg===Store.stars(world)。

## 全局系统（对应必改 1、16、17、18、19、20）

### G1 星轨系统（必改 20）
每关通关时，本关的"数学证据"（十格结构线 / 配对线 / 天平横梁 / 藤蔓彩虹弧 / 十仓轮廓 / 跳跃弧链）
收拢成一截**发光星轨**飞出场景，接到世界地图上该世界与天空之间的轨道上；本世界的星星沿星轨前进一站。
十星集满时星轨全线点亮，星座绽放（复用现有 constellation 绘制）。
实现：Link canvas 已有的线/弧 + 地图上一条 SVG 折线轨道，每世界一条颜色。测试钩子 `window.__trail={world,seg}`。

### G2 「证据变符号」仪式（必改 1、16）
- 算式**从不先出现**。孩子完成构造、结构显形之后，算式条才从证据处"抽出来"：
  结构线收缩为算式的骨架，数字从对应实物组的位置飞入对应的位置（不再是"所有实物变数字"）。
- 全程只在这一刻讲概念总结句；构造过程中 TTS 只报数字/短语（必改 9）。

### G3 提交时刻与容错（必改 2、17、18）
- 每关都有明确的提交控件（绿色按钮或"最后一块落下"），**构造中的任何点击不计错**、可撤销。
- 错误反馈永远显示"差在哪"：少了→缺口位置闪黄框并报"还差两个"；多了→多出的实物弹回原处并报"多了一个"。绝无干巴巴的红叉。
- 所有动画单步 ≤300ms，可连点打断；测试模式 `window.__fast=1` 时动画时长归零。
- 统一暴露：`window.__q={world,kind,phase,target,draftValue,committed,…}`（各关补充 cutIndex/left/right/overflow/jumpSeq）。

### G4 四个通用内核（必改 19）
1. **QuantityBuilder 数量构造器**：点空地生成实物 / 点实物删除，维护 draftValue，提交回调。
2. **SlotRack 槽位架**：n 个可见槽位（虚线剪影），实物入槽/离槽，维护 filled。
3. **Allocator 左右分配器**：两个目标区，轮流/自由分发，维护 left/right。
4. **CommitFlow 提交演示控制器**：提交→判定→证据动画→算式抽出→星轨收束，统一时序与语音。
六个世界 24 关全部由这四个内核 + 各自皮肤组成。

## 世界一 · 佩奇泥坑 →「会排队的泥点」（必改 3、4）
**玩具**：空地 + 大泥脚印按钮（点一次溅一个泥点，落在随机位置）+ 冲呀按钮。
- L1 快照构造：闪 3–5 个泥点（1 秒）→ 布幕遮住 → 孩子用脚印按钮**做出同样多**（位置随意，可点泥点删除）→ 按冲呀提交。
- L2 两跳合并：红泥点 a 个、蓝泥点 b 个先后闪现 → 构造**总数**。
- L3 雨水冲走：闪 n 个 → 当着面雨冲掉 k 个 → 构造**剩下的**。
- L4 篮子捉迷藏：报总数 n 并全部闪现 → 篮子扣住一部分只露 a 个 → 构造**被扣住的**。
**提交后魔法**：孩子的散乱泥点被一朵大水花掀起，空中翻滚后**啪、啪、啪自动排成 2×5 十格结构**；
原题泥点同样排成一行滑入上方，两行逐列对齐比较——对上的列亮绿。乱泥自己显出"五和几"。
**错误反馈**：少两个→十格结构里空两格闪黄"还差两个"；多一个→多出的泥点自己跳回脚印里。
**测试钩子**：`draftValue`、提交后 `structured:true`。
**素材**：全 CSS/SVG（泥点已有）。

## 世界二 · 冒险湾 →「救援配对拉链」（必改 5、6、7）
**玩具**：坡道 + 海滩上的求救海龟 + 待命狗。核心动词：**配对**。
- L1 一一配对：n 只海龟排在浅滩，每只头顶一个空狗位剪影；孩子点一只狗→滑下坡道→跑到下一只海龟身边**拉起一条安全带线连成一对**。全部配对后提交自动亮。
- L2 补缺口：已有 a 对配好（灰色），只剩 n−a 只海龟孤单闪烁 → 只补缺的。
- L3 归队点名：任务完成回营，k 只跳车跑回狗窝（点名板划叉）→ 车上剩下的狗一只只**点亮点名**（同一只不能重复点，点过的有编号徽章），全部点完数字自动显示——不靠孩子口头报数。
- L4 双座救援舱：每只狗开一个**双座舱**下来，一舱正好装 2 只海龟（看得见两个座位）→ d 个舱救完，安全带线"唰"地全部拉直，**舱阵折叠成整齐的 2×d 阵列**，边缘依次亮出 2、4、6、8。成双结构真的变成乘二结构。
**多点保护**：多点的狗在坡道口被门温和挡住摇头（不上车、不挂车尾、不奖励错误）。
**测试钩子**：`paired/total`、L3 `litCount`、L4 `pods`。
**素材**：双座救援舱外壳 → **imagegen**（透明底、无文字无角色无座位线，座位用 SVG 覆盖）。

## 世界三 · Bluey 后院 →「公平大天平」（必改 8、9）
**玩具**：大天平（角度=左右数量差的映射+缓动，不做真实物理——工程红线 2）。饼干点击飞上/飞回。
- L1 谁多多几：a、b 自动上盘，板倾斜 → 孩子往轻的一边一块一块加，每加报一个数，放平瞬间"当~"+
  横梁亮出水平线 → "你加了 2 块才平——Bluey 就是多 2 块！"差 = 配平所需的量。
- L2 指定配平：只许给 Bingo 加（Bluey 盘上锁图标）。放平后算式 b+□=a 从横梁抽出。
- L3 单双数审判（修正物理：必改 8）：n 块饼干，孩子**一块一块轮流**发到两盘（强制左右交替，发错边的那块会自己飞到正确的盘）。
  双数：最后一块落下的瞬间板子水平锁定+彩带。
  单数：发到最后**剩下一块**拿在手里没处放——放左边左沉、放右边右沉（演示两次）→ 它退回中间的聚光灯里孤零零转圈 → "单数：总有一块配不成对"。
- L4 自主平分：n 块（6–12）自由分给两盘，目标放平；放平后每盘数量显形 → "每人 4 块"。不做数字预言（必改 9），
  分错时板子倾斜方向就是提示（重的一边往下沉=多了）。
**测试钩子**：`left/right/balanced`。
**素材**：全 CSS（天平已有组件，升级为可交互目标区）。

## 世界四 · 葫芦山 →「花结与彩虹」（必改 10、11、12）
**玩具**：藤上 N 个葫芦，葫芦之间是**大花结按钮（≥64px，摇摆发光）**，点花结=剪断。
- L1 藤上第几个（保留摘葫芦变身）。
- L2 倒着数（保留，方向箭头动画沿藤跑一遍）。
- L3 剪出算式：左筐里先站着 x 个葫芦剪影（目标可见）→ 孩子选一个花结剪 → 左段滑进左筐与剪影逐个重合。
  重合成功后算式 x+□=N 才从筐沿抽出（先做后式：必改 16）。剪错位置→两段藤弹回接好，缺口/多出的剪影闪黄。
- L4 分法收集（明确语义：必改 11——**收集"无序分法"，7 收集 1+6、2+5、3+4 三组**）：
  每剪一次，剪下的两段藤**各自卷成一段彩色弧，首尾相接拼成一条总长恒定的双色彩虹**（长度=数量，比例可见：必改 12）；
  剪出镜像分法（5|2 之于 2|5）时，两条彩虹旋转重合——"换边，总数不变"，然后合并记为同一组。
  一局收集 2 组即通关，第三组跨局保存（同一个 N 再来时彩虹带着上次的进度）。集齐时整条彩虹绽放+星轨收束。
**测试钩子**：`cutIndex/collected[]`。
**素材**：剪刀+花结 SVG；彩虹=SVG 渐变弧。

## 世界五 · 复仇者 →「能量十仓」（必改 13、14）
**玩具**：能量机器（imagegen 外壳，中央矩形空区）+ **十格能量仓**（DOM 十格）+ 数码屏。
**计数单位是能量球**（发光圆球，CSS）；英雄只负责叙事：每个英雄跑进来**投一颗球**进仓（必改 13：不复制 13 个英雄）。
- L1 充能：a 个英雄投红球 + b 个投蓝球 → 仓里 a+b 格亮 → 读数。
- L2 断电：n 格亮着，传送门吸走 k 颗球（格子逐个熄灭滑向传送门）→ 剩几格亮。
- L3 全息缺口：任务需 n 格满，已亮 a 格，缺的格全息闪烁 → 孩子点传送门补球，补到刚好（多点一次传送门会"嗡"一声不出球——满了）。
- L4 凑十爆仓：已有 8 颗，又来 5 颗排队进仓 → 第 9、10 颗填满十仓，**仓体锁定、金光、盖"10"印章、整仓收拢成一根"十条"**（必改 14：一个十仓+散的一，结构保留）；剩 3 颗排进第二仓 → 屏显"10 和 3 = 13"。
**测试钩子**：`filled/overflow/locked`。
**素材**：机器外壳 → **imagegen**（可选，背景够好就省）；球/格/印章 CSS。

## 世界六 · 花果山 →「三颗仙桃」（必改 15）
**玩具**：12 格石墩数轴 + 骑棒悟空（保留全部既有招牌：逐格蹦、弧线、双数金轨、镜像翻倍、十号金门）。
- L1 接着数（保留）。
- L2 二连筋斗（保留）。
- L3 如意变变变（保留镜像分身）。
- L4 三颗仙桃：起点 6 或 7（预搭好），终点 11 或 12（金门在 10）。悟空只有**三颗仙桃=只能跳三次**，
  每跳吃掉一颗（桃子图标逐个变核）。按钮「跳1」「跳2」。要前进 5 格 → 唯一解是 {2,2,1} 的某个排列。
  跳完第三下即提交判定：不到/超过 → 悟空荡回起点，桃子恢复，弧链保留虚影提示"上次跳了 1+1+2=4，还差 1 格"。
  成功后：**金色悟空残影按相反顺序重跳一遍**（孩子 1+2+2 → 残影 2+2+1），同时落在终点石墩，
  三段弧叠成同一根 5 格长的金箍棒——"顺序换了，总数不变"。跨十那一跳的弧在金门处自动分成蓝金两截。
**测试钩子**：`jumpSeq/peaches/committed`。
**素材**：仙桃 SVG（或复用现有 gourd 调色）。
