## 维度 1 · 幼儿教学法

### 1-1 [严重] 学习顺序没有落实，六岛可自由进入 → **已修复**
- 世界顺序改为认知发展顺序：**佩奇(瞬识) → 汪汪队(一一对应/基数/Give-N) → Bluey(比较/守恒) → 葫芦娃(序数/部分整体) → 复联(合并加法) → 西游记(接着数)**，地图按此顺序排列。
- 加了**跨世界先修门控**：初始只开放前两个；上一个世界达到 **L2 且 ⭐≥4** 才解锁下一个（`Store.unlocked()`）。锁住的世界点击会由语音引导回到前一个世界并高亮它。
- 解锁做成**粘性**：一旦打开永久保留，孩子不会因为掉一级而失去已开放的世界（`Store.refreshUnlocks()`）。
- 序数确实只是支线：葫芦山 L1/L2 是序数，**L3/L4 才是部分-整体**，序数不构成部分整体的先修。

### 1-2 [严重] 六个玩法都能靠猜 / 试错通关，Bluey 守恒乱点必过 → **已修复（本轮最大改动）**
建立统一的**每题作答契约**（`newState()` / `record()`）：

> 独立作答并主动提交 → 首答判定 → 分技能纠错 → **换一道同构新题复测** → 只有"新题 + 未用提示"的首答才写入掌握证据

逐条对应你的指控：

| 你指出的漏洞 | 现在的做法 |
|---|---|
| Bluey 守恒**任何答案都推进**，乱点通关率 100% | 答错**不给星、不进下一轮**；进入"孩子亲手一一配对"纠错（点上面一个→点下面一个连线），配完自己看结果，然后**换一个新排列的同构题重测**。测试 `B5` 断言答错后星数不增加 |
| 金箍棒可以跟着系统报数一直伸到对岸 | 桥不会自动停。孩子必须**自己判断在第几格停下并按【过河！】提交**，长度不等于目标即判错。且**只能一格一格前进**（点非相邻石墩无效），杜绝"拖到底" |
| 葫芦娃语音同时说"第三个"和"黄娃"，可以直接认颜色 | 语音**只说"第几个"，绝不说颜色**；并且**每一轮把七个葫芦的颜色重新打乱**，颜色不再携带任何位置信息 |
| 复联按一次集结就由系统完成；三选一可猜 | 合并后**孩子必须逐个点数**才出答案卡；答案卡 **4 选 1**；L1/L2 **不报出 a 和 b**（"这边一些、那边一些"），孩子只能自己数 |
| 汪汪队用"差一只/多一只"精确指导，可逐只试到成功 | Give-N 改为**先派完再提交**（【好了！】按钮），**提交前不给任何多/少提示** |
| 佩奇三选一可猜；泥点与答案卡布局相同可图形匹配 | 改 **4 选 1**；并强制 **`apat !== qpat`** —— 答案点阵排列与泥点排列**必定不同**。测试 `B2` 对此断言 |

### 1-3 [严重] "连对 2 次升级"是假阳性 → **已修复**
- 改为滑动窗口掌握判据：**最近 5 次首答中 ≥4 次正确**才升级；**最近 4 次中 ≤1 次正确**才降级（`Store.evidence()`）。
- 三选一改**四选一**，随机猜中率从 33% 降到 25%，配合 4/5 判据，纯猜通过概率 ≈ 1.5%。
- **纠错后的复测题、用过提示的题一律不写证据**（`st.isRetry` / `st.hinted`）。测试 `B3` 断言复测不增加 `tries`。
- 延迟复测：因为每次进入世界都重新按当前 L 出题、且证据窗口跨会话保留在 localStorage，下一次会话自然构成延迟复测。

### 1-4 [严重] 错误统一"一起重数一遍"会破坏目标技能 → **已修复**
每个世界实现**自己的**纠错函数，绝不互相套用：

| 技能 | 纠错方式 | 代码 |
|---|---|---|
| 瞬识 | **按组块呈现**（5 → 先亮 3 再亮 2），绝不逐个数 | `GAMES.peppa.remediate()` |
| 基数 | 才做重数，并强调"最后数到几就是几只" | `paw.remedyCardinal()` |
| Give-N | 数出实际派了几只，与卡片点数**并排比较**指出差多少 | `paw.remedyGiveN()` |
| 守恒 / 比较 | **孩子亲手**一一配对，自己发现结果 | `bluey.handPair()` |
| 部分-整体 | 已有部分**保持不动**，只闪烁"还差的空位" | `hulu.missRemedy()` |
| 接着数 | **保留已有长度不动**，只把新增部分逐格演示 | `monkey.remedy()` |
| 一一对应 | 高亮"没配上对的那些" | `aveng.judge()` 分支 |

### 1-5 [中等] 难度跃迁过快 → **已修复**
核心路径收窄：L1 = 1–3，L2 = 2–5，L3 = 3–6，L4 才到 6–8。守恒、接着数、缺失加数都在 L3+，而 L3 需要先在 L1/L2 各拿到 4/5 的掌握证据。

### 1-6 [中等] 符号没有真正放在最后 → **已修复**
- 新增**全局符号门** `Store.symbols()`：至少**两个世界达到 L3** 才解锁阿拉伯数字。
- 解锁前：金箍棒**不显示数字刻度**，所有答案卡一律点阵。
- 解锁后：答案卡才可能出现数字（`apat==="num"`），且孩子点卡时会读出数字名（**符号学习，不是符号考试**）。

## 维度 2 · 三岁半可用性

### 2-1 [严重] 拖拽（尤其复联蛛丝拖线）三岁半做不到 → **已修复**
**全应用零拖拽**。复联配对改为「点一个英雄 → 再点一个坏蛋」两次大目标点击，连线由系统绘制。葫芦娃分路改为「点山洞/山顶大落区」，Bluey 补齐改为「点篮子」。所有可点目标 ≥ 我们设定的 `--obj`（最小 38px，典型 70–100px）与卡片 `clamp(70px,15vmin,148px)`。

### 2-2 [严重] 纯语音依赖；"听不到声音？"是文字孩子读不懂 → **部分修复 + 部分反驳**
**已修复的部分**：
- 提示条改为**大喇叭图标 + 脉冲动画 + 可点击重试**（点一下就再说一遍），文字降级为副标题给家长看。
- 入口按钮从抽象三角改成**喇叭 + 声波动画**，语义是"开始听故事"。

**反驳的部分：本地录音兜底不做。** 理由：
1. 本项目的素材管线是 GPT Image 2（只出图），没有可用的中文配音资源；引入 60+ 条预录语音会让离线包体积翻数倍，且更新一句话就要重录。
2. 我采用了**更强的替代保证**：**所有玩法在完全没有语音的情况下仍可完整通关**。每一个数学动作都有对应的视觉通道 —— 点数时物体跳动 + 编号角标 + 屏幕大数字浮标（`#numpop`）+ WebAudio 音高递增；指令有分级提示（发光 → 手指演示动画）。测试在 headless 无中文 voice 环境下跑通全部关卡，就是这条保证的证据。

### 2-3 [严重] "右下角长按 3 秒"不是成人门禁 → **已修复**
长按 3 秒后**不再直接进面板**，而是弹出**成人算术验证**（如 `7 + 6 = ?` 四选一，随机出题），答对才进。重置按钮再加**二次确认**（点第一次变成"再点一次确认清空"，4 秒后自动复位）。测试 `F` 断言"长按后只出现验证门、面板不可见"。

### 2-4 [中等] "够/不够/正好"语义重叠、缺非文字图标 → **已修复**
- 比多少改为三个**角色/图示**按钮：`Bluey 多` / `一样多`(两排等量圆点 + 等号) / `Bingo 多`，直接点那个角色。
- 复联改为 `英雄不够` / `正好` / `英雄多了`，每个按钮画**上下两排圆点的多寡对比**（3v4 / 3v3 / 4v3），与题目实际数量无关，因此**不能靠图形匹配作弊**。

### 2-5 [中等] 提示不足以让孩子自救 → **已修复**
三级提示（`App.armHint`，每 9 秒推进一级）：**① 可操作对象发光 → ② 重播短指令 → ③ 手指图标演示位置**，之后在 ②③ 间循环，**永不替孩子作答**。孩子一作答立即收起（`record()` 里调 `ctx.clearHint()`），不会在纠错动画里插话。

### 2-6 [中等] 会话真实操作量没控制 → **已修复**
每次进入 5 轮即结束回到星空图（约 2–3 分钟）。葫芦娃分解**不再要求集齐所有分法**：自由探索轮分完两条路即可通关。参与奖励（星星）与掌握证据（`hist`）**分开记录**，家长面板分别可见。

## 维度 4 · 代码质量

### 4-1 [严重] 需要状态机 + session token + 统一清理 → **已修复**
- 全局 `SESSION` 令牌：`nextSession()` / `alive(tok)`，进入世界、离开世界都换令牌；**所有异步回调先校验 `ctx.alive()`**，杜绝旧回调改新页面。
- 每题状态对象 `st = {isRetry, hinted, wrongs, recorded, done}`，`st.done` 之后所有输入路径立即返回。
- `Timers()` 集合统一持有 setTimeout/setInterval，`leave()` 一次性 `clear()`；`destroy()` 释放引用；`#play` 整体清空。测试 `E` 断言反复进出 8 次后 `#play` 残留节点数为 0。

### 4-2 [严重] 语音职责重复；"每个数词单独 speak"与"只保留最新"冲突 → **已修复（这条是本轮第二大改动）**
你说得对，这是架构冲突。现在是**单一语音管理器 + 两条明确策略**：
- **指令通道 `Speech.say()`**：latest-wins，安全打断（`cancel()` → 等 ≥160ms → `speak()`）。
- **计数通道 `Speech.count()`**：**绝不调用 `cancel()`**。引擎忙就等（120ms 轮询），只保留最新一条待播，播完若还有新的立刻接上。这样既不会产生取消风暴，也不会把刚起播的数词掐断。
- 关键补充：**计数的完整性由视觉与音效通道保证，不依赖语音** —— 每点一下都有编号角标、大数字浮标、音高递增的 WebAudio 音，所以即使语音只报到最新的数，孩子看到的计数序列也是完整的。
- 指令优先于计数：`say()` 会清掉待播的计数（`cntLatest=null`）。

### 4-3 [中等] 存储 schema 不够 → **已修复**
`kidmath2.progress.v2`：每个世界 `{stars, lv, hist[≤8], seen, tries, open}`。`hist` 就是**首答证据序列**（复测/提示题不入列）。读入时 `try/catch` + 逐字段类型校验 + 范围夹取 + 版本不符回默认值。测试 `E` 写入 `'{{{ broken json'` 后断言仍能正常启动。

### 4-4 [中等] SW 缺超时/版本/原子性 → **已修复**
`sw.js`：`VER` 版本化缓存（`shell-v* / media-v*`），`activate` 删除所有非当前版本；页面/manifest **网络优先 + 2.5 秒超时**回落缓存；`assets/*` 缓存优先；跨域请求不拦截。

### 4-5 [中等] 测试没验证教学与生命周期不变量 → **已修复**
新增断言：答案卡 4 张且数值互不重复、题面排列 ≠ 答案排列、答错不升级且立即写入失败证据、复测题不写证据、守恒题等量且物体尺寸集合唯一、乱点不通关、反复进出无残留、localStorage 损坏可启动、竖屏零滚动、连点压力下无语音踩踏。

# 附：本轮自动化测试自己抓出来的问题（已修）

第一轮 Playwright 全量跑出 110 通过 / 17 失败，收敛成 4 个根因。其中三个是**真 bug**，值得单独说明，因为它们正好印证了你在第一轮提出的两个担忧：

### T-1 计数通道违反军规②（cancel → speak 间隔 <150ms）
语音时间线断言直接抓到 `sinceCancel=44ms`。原因：我按你的意见把计数拆成独立通道后，**忘了让计数通道也遵守 CANCEL_GAP** —— 当指令刚 `cancel()` 并排了 160ms 的定时器，孩子这时点了一下物体，计数会立刻 `speak()`，落在禁区里。在 iOS 上这正是把队列卡死的那种写法。
修复：`Speech.count()` 的 flush 增加两道闸门 —— 距上次 `cancel()` 不足 `CANCEL_GAP` 就重排；指令通道有待播条目时让路。

### T-2 ⭐ 连续答错会把孩子卡死在同一轮（最严重）
原设计是"错两次就直接给答案"，但**每次纠错后都会生成同构新题、`st` 是新对象、`wrongs` 归零**，于是"错两次"永远达不到。一个总是答错的孩子会：错 → 纠错 → 新题 → 错 → 纠错 →… **永远拿不到星星、也永远等不到答案**。对三岁半这是最糟糕的失败模式。
修复：引入**跨复测的每轮失败计数** `fails`，只在 `next()`（真正进入下一轮）时清零。判据改为 `st.wrongs>=2 || fails>=2` → **任何一轮最多错两次，之后系统一定给出答案、带着孩子做对、给星、进入下一轮**。六个世界全部套用。
并加了断言 B6：一直答错时，最多 N 次后必须给出答案并推进。

### T-3 `onTap` 的 200ms 去抖会静默吞掉连续点击
"连点同一个大按钮来增加数量"是三个世界的核心交互（葫芦山派人、Bluey 加饼干、汪汪队派狗）。200ms 去抖窗口意味着**孩子点快一点就有一半的点击被丢掉，而且毫无反馈**。
修复：去抖窗口降到 70ms（只用于防同一次物理触摸的重复派发）。

### T-4 竖屏被拉高导致"小物体飘在大空场里"
竖屏下 `ztop` 高达 1050px，按百分比定位的角色变成巨人并压住计数区，而按宽度定尺寸的计数物又很小。
修复：舞台加一层**固定长宽比（≤64vw）、贴底对齐**的 `.stage` 容器 —— 横竖屏共用同一个坐标系，角色改为宽高双向受限。竖屏走查全部重跑通过（零滚动、零溢出）。

### 顺带修掉的
- 地图卡片里的角色在窄卡片下被裁切 → 改为按宽度分配（每张卡 3 个角色）。
- `paw.giveAnswer` 原本靠合成 `PointerEvent` 复用点击逻辑 → 抽成具名函数 `sendDog()/recall()` 直接调用。
- 删掉未使用的 `actor()` 助手、`.actor` 样式、`practice()` 空壳、`gotStar` 死变量，以及两个未被任何玩法引用的素材（不再预载）。
- `onTap` 对同一节点重复绑定时先摘旧监听（`#cheer` 每次通关都会重绑，原来会持续堆积）。

### 测试脚手架自身的两个错（不是应用的问题）
- `play_session` 在上一轮刚得星、新题还没建好时就去点旧 DOM → 现在必须等 `window.__qn` 递增。
- "指令 3 秒内重复"断言把数词也算进去了（数词本来就会反复出现）→ 现在只统计长度 ≥8 的指令级文本。

# 附二：本轮我自己又补上的三处（未经你指出，但属于同类问题）

### S-1 花果山 L3/L4 还留着一条"视觉对齐"捷径 —— 已补上真正的算术判定
目标旗是给不识字孩子的位置提示，但"把桥点到旗子那里"可以纯靠视觉对齐完成，**不构成"接着数"的证据**。
现在改成两段：**把桥搭到亮着的石墩**只算操作（连错两次系统会带着孩子放到位，**不计证据**），到位之后必须再答一题
**「你一共加了几格？」**（四选一，答案 = `need`），**证据只记在这道题上**。答错走"接着数专用纠错"：保留已有的 `pre` 格不动，只把新增的逐格点亮报数。

### S-2 连续两题不再出同一道
原来相邻两轮可能生成完全相同的题目，孩子会连着听到一模一样的指令（测试的"3 秒内重复"断言正是这么抓到的）。
现在六个世界统一用 `fresh(gen, key, box)` 重掷，相邻两题的关键参数必定不同。

### S-3 `utterance.voice` 赋值加了容错
有的引擎只接受它自己的 `SpeechSynthesisVoice` 实例，赋错类型会**直接抛异常**——而这句正好在入口 `click` 的同步栈里，
一抛整个启动流程就断了（首句不出声、地图也进不去）。现在 `try/catch` 包住，并总是显式设 `u.lang`。
这个问题是测试桩替换 `getVoices()` 时暴露出来的，但在真机上"系统返回了不合规的 voice 对象"同样会触发。

### 顺带
- 入口 `click` 处理器里把 **TTS 首句提到最前**（AudioContext 与无声 audio 循环紧随其后，三者仍在同一个 click 任务里）——最脆弱的一步优先。
- 「听不到声音」提示条移到顶栏下方，不再遮住关卡进度点。
- 新增测试 **H 组**：在**完全没有 `speechSynthesis`** 的环境下（模拟 iPad 上一个中文声音都没装），仍必须能启动、出现喇叭提示条、并把三个世界各玩满 3 轮。这是我对"不做本地录音兜底"那条反驳的**可执行证据**。

### S-4 Bluey 比较关补上"长度线索"的三级梯度
原来 L1 和 L2 两排都**铺满同样宽度**，等于一上来就把"排得长=更多"这个知觉线索抹掉了；
更糟的是它会顺手教出"排得开=更少"的错误概括，而 L3 守恒关恰恰要打破这个概括 —— 顺序装反了。
现在改成：

| 级别 | 排布 | 目标 |
|---|---|---|
| L1 | **固定间距**（`rowFixed`）—— 排得越长就是越多 | 允许用知觉直接比，这是三岁半正常的第一策略 |
| L2 | **两排铺满同样宽度**（`rowPos`）—— 长度线索被抹掉 | 必须去看数量本身（密度/点数） |
| L3 | **守恒**（`rowSpread`）—— 数量相同、只有间距不同 | 外观主动误导，只有真正数了才对 |
| L4 | 固定间距 + 补齐到一样多 | 从比较走向"差多少" |

这样 L1→L3 是一条"先建立知觉策略、再让它失效、最后被数量取代"的完整路径，而不是把两种线索随机混在一起。
