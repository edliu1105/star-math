# 《星星回家》— 幼儿数感建构互动应用 · 设计方案 v1

**目标用户**：3 岁半（快 4 岁）儿童，说中文，**不识字**。设备：iPad（Safari / Chrome，均为 WebKit）。

**唯一目标**：让孩子**真正理解**数字、数量与加法 —— 是理解，不是背诵。

---

## 1. 教学法根基（为什么这样设计）

### 1.1 这个年龄真正需要建立的认知，按发展顺序

| # | 认知能力 | 说明 | 为什么关键 |
|---|---------|------|-----------|
| 1 | **瞬识 Subitizing** | 不数就知道 1–3（知觉瞬识）、4–6（组块瞬识）有几个 | 数感的生物学基础，**先于**计数。是"量"的直觉，不可能靠背诵获得 |
| 2 | **一一对应 One-to-one** | 每个物体配一个且仅一个数词 | 计数五原则之首 |
| 3 | **基数原则 Cardinality** | 数到的**最后一个数词 = 整个集合的数量** | ⭐ 3–4 岁最关键的飞跃。大量孩子能流利背 1–10 却答不出"一共几个"——这正是**背诵与理解的分水岭** |
| 4 | **Give-N（取出 N 个）** | 听到"给我 5 个"能取出正好 5 个 | Gelman 经典测验，最能区分"会数"与"懂数"。**背诵者无法通过** |
| 5 | **比较 Comparison** | 多 / 少 / 一样多 | 数量关系的起点 |
| 6 | **守恒 Conservation** | 摆开或挤紧，数量不变 | 皮亚杰经典。检验孩子依赖"看起来大"还是"真的数量" |
| 7 | **部分—整体 Part-Whole** | 5 可以是 1+4、2+3…… | 加法的**结构**理解（number bond），而非算式记忆 |
| 8 | **合并加法 Count-All** | 两堆合起来，全部重数一遍 | 加法的第一个真实含义 = 集合合并 |
| 9 | **接着数 Count-On** | 从 3 开始往后数 2 个 → 5，不必从 1 重数 | ⭐ 从"数数"到"运算"的飞跃，加法策略的第一次真正抽象 |
| 10 | **符号映射** | 把阿拉伯数字贴到**已理解的量**上 | 放在最后。符号是量的名字，不是数学本身 |

### 1.2 明确拒绝的反模式

- ❌ 全程"3 + 2 = ?"四选一 → 退化成模式匹配 / 记忆检索
- ❌ 语音直接念"三加二等于五"而不让孩子亲手合并 → 灌输结论
- ❌ 一上来就要求认数字符号 → 3 岁半是量感期，符号是最后一步
- ❌ 用文字出题（孩子不识字）
- ❌ 错误惩罚（红叉、扣分、失败音效）→ 3 岁半最怕挫败，会直接放弃
- ❌ 六个 IP 换皮同一个玩法 → 无教学增量，也浪费角色特性

### 1.3 核心方法论：**手做数学，不是眼看数学**

每一个数学动作都必须由孩子的手指完成，屏幕给出即时的**物理响应 + 语音同步**：

- 点数 → 每点一个，物体**跳起 + 亮起 + 打上标记**，同时语音报数 → 一一对应具身化
- 数完 → **必须回答"一共几个"** → 基数原则检验
- 合并 → 真的看到两堆**飞到一起** → 加法 = 合并
- 接着数 → 金箍棒**一格格变长**，从已有长度继续 → count-on 具身化
- 分解 → 把一堆**真的分到两边** → part-whole 具身化

## 2. 世界观

> 夜里刮了一场大风，天上的星星被吹掉了，散落到六个不同的世界里。
> 每个世界的朋友们都需要小朋友帮忙 —— 帮一次忙，就找回一颗星星。
> 星星飞回天上，慢慢连成星座。六个星座都亮起来时，天空就修好了。

- 主界面 = **星空地图**，六个发光的岛（六个世界）。
- 每通一关 → 一颗星飞上天。
- 一个世界集满 → 天上点亮该世界的专属星座。
- 全部点亮 → 烟花 + 全体角色合影。

**为什么用这个框架**：给"数一数"一个孩子能理解的动机（帮朋友），奖励是**可累积、可见、非随机**的（星星数量本身就是数量表征——星空也是一个数感教具）。

## 3. 六个世界 × 六个数学概念（机制必须来自角色本身的能力）

### 🍑 世界一 · 花果山｜**金箍棒搭桥** —— 数轴 / 接着数 (Count-On)
- **角色**：孙悟空（主）、唐僧、猪八戒、沙僧、白龙马（在对岸等待）
- **机制来源**：如意金箍棒**能变长变短** —— 天然就是一根**数轴**
- **玩法**：河上一排石墩（数轴刻度 0…10）。悟空把金箍棒当桥。
  - 语音："变长 3 格！" → 孩子每点一下，棒子长一格，报数 "1！2！3！"
  - "再变长 2 格！" → **从 3 接着数 "4！5！"**（不重头数 ← 这就是 count-on）
  - 桥正好搭到对岸 → 师徒四人 + 白龙马依次过桥
- **难度**：L1 一次变长（纯计数）→ L2 两次变长（count-on 加法）→ L3 同时显示数字符号 → L4 **缺失加数**（"桥要 7 格，现在 4 格，还差几格？"）
- **反馈**：短了 → 大家在对岸招手"还差一点点，再数数看"；长了 → 悟空缩回来。零惩罚。

### 🎋 世界二 · 葫芦山｜**七兄弟分头救爷爷** —— 序数 + 部分整体 (Part-Whole)
- **角色**：七个葫芦娃（红橙黄绿青蓝紫 = 天然的 1–7 有序序列）、爷爷、蛇精、蝎子精
- **机制来源**：葫芦按彩虹顺序在藤上成熟；七兄弟**各有本领、按顺序出场**
- **玩法 A（序数）**：藤上七个葫芦。爷爷喊"该**第三个**——黄娃啦！"孩子点第 3 个葫芦 → 黄娃破壳。建立"第几个"≠"几个"。
- **玩法 B（分解）**：救爷爷有**两条路**（山洞 / 山顶），蛇精守一条、蝎子精守一条，**两条都得有人**。
  - "要 5 个葫芦娃！"孩子把葫芦娃拖分到两条路 → 看到 5 = 1+4 = 2+3 = 3+2 = 4+1
  - 每发现一种分法，点亮一格"分解表"，集齐全部分法通关
  - 语音："左边 2 个，右边 3 个 —— 合起来还是 5 个！"（守恒 + 交换律直觉）
- **难度**：L1 序数 1–3 → L2 序数 1–7 → L3 分解 4/5 → L4 分解 6/7

### 🛡️ 世界三 · 复仇者大厦｜**集结！** —— 合并加法 (Count-All) + 一一对应
- **角色**：钢铁侠、美国队长、雷神、绿巨人、黑寡妇、鹰眼、蜘蛛侠、黑蜘蛛侠
- **机制来源**：英雄从**不同入口集结**（昆式战机 / 传送门）；蜘蛛侠**射蛛丝**
- **玩法 A（集结加法）**：左边战机降落 N 个英雄，右边传送门出来 M 个 → 孩子按【集结！】→ 两队真的飞到中间**合并成一堆** → 一起点数总数 → 选出对应点阵
  - 这是加法最原始的含义：**两个集合的并集**
- **玩法 B（一一对应 / 够不够）**：N 个小怪来袭，只有 M 位英雄。孩子从每位英雄拖一根**蛛丝**连到一个小怪 → 一一对应
  - 连完问："英雄够不够？"→ 够 / 不够 / 正好 → 比较与配对
- **难度**：L1 和 ≤ 5 → L2 和 ≤ 10 → L3 合并后不重数、直接接着数 → L4 显示数字符号

### 🚒 世界四 · 冒险湾｜**汪汪队救援：正好够！** —— 基数原则 + Give-N
- **角色**：莱德、阿奇、毛毛、天天、灰灰、路马、小砾（7 只，各有救援场景）
- **机制来源**：莱德在屏幕前**派任务**，"每只狗一个岗位"是汪汪队的固定叙事
- **玩法**：
  1. 莱德的大屏幕显示险情：沙滩上 N 只小海龟回不了海 / N 个箱子要搬
  2. 孩子**点数**（每点一只，海龟抬头 + 报数）
  3. ⭐ **必答**："一共几只呀？" → 基数原则检验（点阵作答）
  4. ⭐ **Give-N**：从狗窝里"派出正好这么多只狗" → 拖出正好 N 只
  5. 多了/少了 → 阿奇："我们还差一只！" / "多来了一只，回去啦～"（自然叙事反馈）
- **难度**：L1 数量 1–3 → L2 1–5 → L3 1–7 且**打乱排列**（顺序无关原则）→ L4 数完后追问"再来一只是几只？"

### 🐕 世界五 · Bluey 家后院｜**公平游戏** —— 比较 + 数量守恒
- **角色**：Bluey、Bingo、爸爸 Bandit、妈妈 Chilli
- **机制来源**：Bluey 的灵魂就是**假装游戏**与**公平**（"这样公平吗？"是剧里的高频台词）
- **玩法 A（一样多）**：Bluey 和 Bingo 分东西（冰淇淋球 / 枕头 / 贴纸），必须**一样多**才公平。孩子拖东西过去直到两边相等。
- **玩法 B（守恒）** ⭐ 皮亚杰实验游戏化：Bandit 爸爸把 Bingo 的饼干**摆得很开**，Bluey 的**挤在一起**（数量其实相同）。
  - 问："谁的多呀？"→ 孩子选
  - 无论选什么，都**一起一一对应数一遍**（连线动画）→ "原来一样多！"
  - 这是全场最能暴露"看表象 vs 懂数量"的一关
- **难度**：L1 明显多少（2 vs 5）→ L2 接近（4 vs 5）→ L3 守恒（等量不同排布）→ L4 "再拿几个就一样多？"

### 🐷 世界六 · 佩奇的泥坑｜**跳泥坑！** —— 瞬识 Subitizing
- **角色**：佩奇、乔治、猪爸爸、猪妈妈
- **机制来源**：佩奇的标志性行为就是**跳泥坑溅泥点**——天然的"闪现一堆东西"
- **玩法**：佩奇跳进泥坑 → 溅起 N 个泥点，**只闪现约 1 秒就消失**（时间不够数 → 强迫用瞬识）
  - 孩子从 3 张**点阵卡**中选出对应数量（**点阵而非数字**：不识字也能玩，且训练量感而非符号）
- **难度**：L1 1–3 随机排列（知觉瞬识）→ L2 4–5 → L3 **结构化排列**（骰子点 / 两组）= 组块瞬识 → L4 点阵 ↔ 数字符号配对（符号引入的最佳时机）

### 概念覆盖检查

```
佩奇   → ① 瞬识
汪汪队 → ② 一一对应  ③ 基数  ④ Give-N  (+ 顺序无关)
Bluey  → ⑤ 比较      ⑥ 守恒
葫芦娃 → 序数        ⑦ 部分-整体分解
复联   → ⑧ 合并加法(count-all) + 配对/够不够
西游记 → ⑨ 接着数(count-on) + 缺失加数
全局   → ⑩ 符号映射（各世界 L4 统一引入数字）
```
路径完整：**量感 → 计数 → 基数 → 比较 → 结构 → 运算 → 符号**。

## 4. 交互与可用性（3 岁半专项）

| 项 | 决策 |
|---|---|
| **文字** | 界面**零文字依赖**。所有指令用语音 + 图标 + 动画演示。仅家长面板有文字 |
| **点击目标** | ≥ 88×88 CSS px（远超 44px 标准），间距 ≥ 20px |
| **指令重复** | 点击角色头像 = 重听一遍。8 秒无操作自动温柔提示一次（只提示一次，不唠叨） |
| **错误处理** | 无红叉、无失败音、无扣分。角色友善引导 + **一起重数一遍**（把错误变成教学时刻） |
| **首次演示** | 每个世界第一次进入，角色**做一遍示范动画**（手指图标点给孩子看） |
| **自适应难度** | 连对 2 次升一级，连错 2 次降一级，各世界独立，存 localStorage。等级对孩子不可见 |
| **会话长度** | 每关 4–6 题，通关即放星星回天，避免疲劳 |
| **退出/返回** | 左上角大房子按钮回星空图，无二次确认（孩子按错也没关系） |
| **家长入口** | 右下角**长按 3 秒**（孩子难以触发）→ 家长面板：进度、语音诊断、重置 |
| **朗读风格** | 短句、慢速（rate 0.85）、数数时每个数词单独一次 speak（与动画同步） |
| **横竖屏** | 均可用。核心区用 flex + clamp()，竖屏时纵向堆叠 |

## 5. 技术架构

- **单文件** `index.html`（内联 CSS/JS，vanilla，零依赖）+ `assets/`
- **PWA**：`manifest.webmanifest` + `sw.js`
  - 页面 (`index.html`, `sw.js`, manifest)：**网络优先**（改 bug 后能立刻拿到新版）
  - 素材 (`assets/*`)：**缓存优先**（离线可玩、加载快）
- **状态**：localStorage（`kidmath2.progress.v1`：各世界等级、星星数、已解锁星座）
- **触控**：`touch-action: manipulation`、`contextmenu` preventDefault、`user-select:none`、禁双击缩放
- **音频**：见第 6 节（iOS 军规）
- **图形**：所有美术素材为 GPT Image 2 生成的 PNG（角色/背景/道具）；纯几何 UI（按钮底、进度条、连线）用 CSS/Canvas

### 模块划分（单文件内的逻辑分区）
```
Audio      —— TTS 安全层 + WebAudio 音效 + 静音开关绕过
Speech     —— 队列/安全打断/兜底超时/诊断
Progress   —— localStorage 读写、自适应难度
Router     —— 星空图 ↔ 世界 ↔ 关卡
Games×6    —— 每个世界一个独立模块（init/step/teardown）
FX         —— 星星飞行、粒子、角色动画
Parent     —— 长按入口、诊断面板
```

## 6. iOS / iPadOS WebKit 语音军规（硬性）

1. **首次解锁**：入口按钮用 `click`（非 pointerdown），在**同步调用栈内**直接 `speak()` 第一句，**不包 setTimeout**
2. **安全打断**：`cancel()` 后 **≥150ms** 才 `speak()`；统一 `safeSpeak()` 函数
3. **不信任 onstart/onend**：
   - 是否在说话 → `speechSynthesis.speaking || pending` **轮询**（speak 后 ~450ms 查一次）
   - 依赖 onend 的流程 → 超时兜底 `max(2500, 字数×380)ms`
4. **每次 speak 前 `resume()`**；`visibilitychange` 转可见时也 `resume()`
5. **WebAudio**：AudioContext 惰性创建 → 每次手势内 `resume()` → 首次手势播一帧无声 buffer；同时**循环播放无声 `<audio>`** 把页面提升为媒体会话，绕过 iPad 静音开关
6. **中文语音选择**：过滤 `lang` 以 `zh` 开头 → 优先 `zh-CN` → 兼容 iOS `Ting-Ting/婷婷`、Windows `Xiaoxiao`；`voiceschanged` 晚到时用正确声音**补说第一句**；保留 utterance 引用防 GC
7. **补说/兜底重说**必须同时满足：引擎 `speaking||pending` 时立即退出；距上次语音请求 **<1.5s 禁止插嘴**；带节流
8. **快速连点**：永远只播报**最新一条**（安全打断），绝不排队
9. **"听不到声音？"提示条**（用引擎状态判定，非事件）+ 隐藏**语音诊断面板**（系统声音数、中文声音列表、当前所选、测试发声）
