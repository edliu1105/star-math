# 审查任务说明（给 gpt-5.6-sol 的固定 brief）

你是这个项目的**严格评审**。项目是一个给 **3 岁半（说中文、不识字）儿童**用的 HTML 互动数学启蒙应用，
目标设备 **iPad（Safari / Chrome，都是 WebKit）**，单文件 `index.html` + `assets/`，vanilla JS，零依赖，PWA 离线可玩。

**唯一产品目标**：让 3 岁半孩子**真正理解**数字、数量、加法 —— 是**理解，不是背诵**。

请从以下**六个维度**逐一审查，每个维度给出：结论 + 具体问题（编号）+ 可执行的修改建议。
不要客套，不要泛泛而谈，指出具体文件/章节/行为。宁可苛刻。

## 维度 1：幼儿教学法（最高权重）
- 教的内容是否真的建构"数感"，还是伪装成游戏的记忆训练？
- 认知发展顺序是否正确（瞬识 → 一一对应 → 基数 → Give-N → 比较 → 守恒 → 部分整体 → 合并加法 → 接着数 → 符号）？
- 有没有让孩子"手做数学"，还是只是"眼看数学 / 听结论"？
- 是否存在能被"猜"或"模式匹配"通过的关卡（即背诵者也能通关）？
- 难度曲线对 3 岁半是否合理？错误反馈是否会造成挫败？

## 维度 2：三岁半可用性
- 不识字的孩子能否**完全靠语音 + 图标 + 动画**独立操作？
- 点击目标大小、误触、返回路径、注意力时长、无操作提示节奏。
- 首次进入是否有示范？孩子卡住时能否自救？
- 有没有孩子会误入的成人界面（家长面板必须难以误触）。

## 维度 3：视觉品质
- 美术是否统一、可爱、适龄；角色是否可识别；对比度与可读性（尤其数量呈现）。
- 布局在横屏/竖屏、不同尺寸下是否成立；有无遮挡、溢出、拥挤。
- 动画是否服务于数学理解（而不是分散注意力的糖）。

## 维度 4：代码质量
- 结构、可维护性、状态管理、内存/事件泄漏、teardown 是否干净。
- 边界条件、竞态（尤其语音与动画的竞态）、localStorage 容错。
- 是否有死代码、重复逻辑、隐患。

## 维度 5：性能
- iPad 上的首屏加载、素材体积、动画帧率、内存占用。
- 是否有布局抖动、强制同步布局、过多 DOM、定时器泄漏。

## 维度 6：iOS / WebKit 兼容（硬性 checklist，逐条核对）
1. TTS 首次解锁必须发生在 `click`/`touchend`/`pointerup` 类"抬起"手势的**同步调用栈**内；`pointerdown` 里 speak 会被 iOS 静默丢弃；入口按钮必须用 `click` 并**直接**说出第一句（不能包 `setTimeout`）。
2. `speechSynthesis.cancel()` 之后必须等 **≥150ms** 再 `speak()`，否则 iOS 上语音队列永久卡死。必须有统一的安全打断函数。
3. 不信任 utterance 的 `onstart`/`onend`（iOS 常不触发）：
   - "语音是否已工作"用 `speechSynthesis.speaking || pending` **轮询**判定（speak 后 ~450ms 查一次）；
   - 依赖 `onend` 的流程必须带超时兜底 `max(2500, 字数×380)ms`。
4. 每次 speak 前调用 `speechSynthesis.resume()`；`visibilitychange` 恢复可见时也 resume。
5. WebAudio：AudioContext 惰性创建、每次手势内 resume、首次手势播一帧无声 buffer 解锁；同时用**循环播放的无声 `<audio>`** 把页面音频会话提升为媒体级别，绕过 iPad 静音开关。
6. 中文语音选择：过滤 `lang` 以 `zh` 开头的 voice，优先 `zh-CN`，兼容 iOS 的 "Ting-Ting/婷婷" 与 Windows 的 "Xiaoxiao"；voices 列表晚到（`voiceschanged`）时要能用正确声音**补说第一句**；保留 utterance 引用防 iOS GC。
7. 游戏内交互可用 `pointerdown` 保灵敏，但任何"补说/兜底重说"逻辑必须同时满足：引擎 `speaking||pending` 时立即退出；距上次语音请求 **<1.5s 禁止插嘴**；带节流。
8. 快速连点触发语音时，永远只播报**最新一条**（安全打断），绝不排长队。
9. 有"听不到声音？"自动提示条（用**引擎状态**判定，不用事件）+ 对孩子隐藏的语音诊断面板（系统声音数量、中文声音、当前所选、测试发声按钮）。
